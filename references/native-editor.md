# 原生规格编辑器

这是 Windows 上共用的轻量 WebView2 外壳，不是项目管理器或 ShadowStage。新项目的 `.kpldoc` 是用户可编辑的唯一规格；机器状态只是引用和证据。项目目录、版本、写入与失效的权威说明见 [项目目录与版本](project-structure.md)，字段见 [用户规格格式](spec-format.md)。

## 实际能力与边界

- 双击规格后先查看，解锁后编辑，Ctrl+S 或保存按钮写回当前文件；关闭有未保存内容时可选择保存、放弃或取消。解锁是防误操作，不是加密。
- 表格显示缩略图、镜号、秒数、一句话内容、景别、镜头运动、已解析引用的资产数及用户标记；详情有描述和图片／视频提示词。时间线与表格共用数据，按秒显示时长，可选镜头、调整顺序与时长，并以静态图、硬切和已有二维裁切参数预览。它不是生成视频或真实表演，不能证明动作、速度、景深或动态验收通过。
- 资产路径按文本限定在项目的 `05_参考资产`；只有 `@{…}` 唯一解析的引用计数，缺失或歧义需处理。宿主未逐级核查资产子目录是否为链接或 junction，虚拟主机的链接行为也未实测：仅使用可信项目及普通目录，不能把它当严格文件隔离。缩略图与引用标记不证明已经上传、模型绑定或视觉验收；按审片流程实际打开总览及必要原图。
- 画幅未填时画面预览暂显示 16:9，不能视为确认。待定时长镜头拖到轨道会写入 2 秒，没有用户明确时长依据时仍需询问。拖动重排会重编显示镜号，但稳定 ID 保留；按 ID 核对其他引用，不能把新编号当新身份。`done` 等是用户标记，不是自动验收证据。
- 品牌与更新检查：程序和窗口带 KPL 图标，顶栏显示 KPL 标识；“关于”弹层写明版本（宿主常量 `AppVersion`）、作者繁星之子卡萨蒂亚和仓库 `AngleNaris/KPL`。启动后宿主在后台静默请求 GitHub 最新 Release（5 秒超时，失败不提示；页面本身仍不能联网），仅在有更高版本时于顶栏提示。点击提示只打开固定的仓库发布页，不下载、不安装；离线不影响使用。
- 缩略图缓存：镜头多、参考图大（单张可达数十 MB）时，界面不直接载入原图。打开规格后宿主在后台把引用到的图片缩成 480 像素宽的 JPEG，缓存在当前用户的 `%LOCALAPPDATA%\KPL\thumbs\`（项目之外，不写入项目目录；文件名由相对路径、大小和修改时间的哈希决定，原图不变就不重做，可随时删除重建），并以只读虚拟主机提供给页面。生成期间状态栏显示“正在生成缩略图 n/总数”；未生成好的图只显示占位、不载入原图，.NET 无法解码的格式（如 webp）同样保持占位。缩略图只是预览，不代表原图已核对；需要核对画面时仍按审片流程打开原图。
- 时长精度：镜头时长只能精确到 0.1 秒，检查脚本和编辑器保存都会拒绝更多位小数（写法见 [用户规格格式](spec-format.md)）。旧文件里的多位小数时长，编辑器打开时会按累计切点规整显示；只读状态下不算改动、不写回，用户解锁后才标为未保存，保存后才生效，规整后需重新核对受影响的切点与卡点。描述超过 300 字时编辑器只提示、不阻止保存，但检查脚本会整体拒读这份规格；时长或描述超限的文件如何处理见 [项目目录与版本](project-structure.md#超限规格的整改)。
- 时间线泳道：左侧是轨道抬头（拖动右缘可调宽度），自上而下为字幕轨、自由视频轨、主轨 V1、音频轨。视频轨的抬头有画面（眼睛）与声音（喇叭）两个开关，音频轨只有声音，字幕轨只有画面；开关写进文档，只读时显示状态但不能改。每行（含标记带）还有锁：锁定后不能拖动、裁剪、分割、删除或新增，联动也不移动它，Agent 同样不改。所有条目（片段、字幕、范围标记、主轨镜头）两侧边缘都能拖：自由轨与字幕裁开头或结尾；主轨镜头拖左缘默认移动与上一镜的切点（总长不变），按住 `Alt` 只改本镜时长。工具条的磁铁开关吸附（`S`）：拖动时贴靠任意轨道的条目边缘、镜头切点、标记和播放头；链环开关联动：镜头时长变化时，切点之后的字幕、自由轨片段和标记跟着平移（移动切点、调整镜头顺序不联动）。两个开关是界面偏好，默认打开。右键片段、字幕、标记、镜头、轨道抬头或空白处，给出当前位置可用的操作。工具条 `+` 可新建轨道、导入字幕，或在播放头插入视频/音频；自由轨条目可拖动、拖右缘裁剪、`Delete` 删除、`Ctrl+K` 分割，`Ctrl+Z`/`Ctrl+Shift+Z` 撤销与重做（内存里的快照，最多 50 步）。
- 字幕：只读取现成的 srt、lrc、ass 文件（`src/Subtitle.cs`）；ASS 的 `\k`/`\kf`/`\ko` 标签与 LRC 的 `<mm:ss.xx>` 给出逐字时间，编辑器不生成文字、不做识别、不自动对齐音乐，这些素材由其他工具或 Agent 准备好。字幕轨始终显示在视频轨之上，监视器底部叠加当前条目，每条字幕轨在抬头用眼睛按钮单独开关显示。也可以在 `+` 菜单里“在播放头新建字幕”手动写一条，选中字幕后在右侧详情栏改文字；改文字不会改逐字时间。
- 标记：标尺下方是标记带。解锁后按 `M` 或标记带左侧的旗子在播放头加点标记，在标记带空白处拖动画出范围标记；拖动标记移动，拖范围标记右缘改终点，`Delete` 删除。选中标记后右侧详情栏显示时间与作者并可写说明。用户写的标记用强调色，Agent 写的用冷灰蓝；Agent 只改自己写的标记（规则见 [格式](spec-format.md#媒体时间线v3)）。
- 镜头视频：解锁后在镜头详情的“视频”块用系统对话框关联已生成的视频（可在对话框里一次多选，同一镜头多次生成的结果都作为版本保存；详情栏列出全部版本，点选即改用，时间线镜头上的 `2/3` 角标表示当前用的是第几个；悬停某个版本会静音循环播放它的采用范围；新加的版本只进候选、不自动切换），时间线监视器在该镜头格内直接播放视频，其余镜头仍是静态预演。第一次加入媒体后保存会把文档升级为 v3（[格式](spec-format.md#媒体时间线v3)），旧版编辑器打不开。镜头时长与视频采用范围相互独立，视频短于镜头时时间线显示斜纹空缺；只有用户选“用视频长度设为镜头时长”才改时长。为了能播放任意文件夹里的素材，宿主启动时把本机、可移动和网络盘的根目录各映射为只读主机，页面只能把它们用作音视频来源（脚本读不到内容，也不能联网），地址只由宿主按文档里的路径生成；这同样不是严格的文件隔离。素材缺失、移动或格式不支持时显示警告，播放不代表视频已验收。
- 窗口：默认约 16:9，关闭时记住窗口大小和最大化状态（与显示、布局偏好同存于 `%LOCALAPPDATA%\KPL\prefs.json`）；时间线面板默认取最小高度。
- 文件保存前检查基线，外部修改或另一个窗口先保存会阻止覆盖；写入后读回。冲突、只读、忙碌、权限失败和写入结果不确定时保留／核实实际文件，再决定如何处理；不要盲目重试或覆盖。
- 导出：顶栏“导出”有两项，都只导出已保存的版本。“导出 HTML 交接包…”生成一个以“项目名_版本_交接包”命名的 zip，内含与编辑器相同界面的只读 HTML（“项目名_版本_交接查看.html”）以及页面实际用到的参考资产图、分镜缩略图和时间线视频（含备选版本与音频），页面按包内路径读图与视频，接收方解压后直接打开 HTML 即可；“导出视频…”按时间线合成 MP4（H.264/AAC）、MOV（ProRes 422）或仅声音的 WAV，格式、分辨率与帧率由用户在弹层里选。视频导出需要系统里已安装 ffmpeg 与 ffprobe（在 PATH 中），编辑器不附带、也不自动下载；没有时会提示。默认存到 `07_预演交付/01_成片导出_v00N_draft.<格式>`，用户可改。导出的视频是预演合成，不代表动态验收。
- 时间线多选：解锁后 `Ctrl`/`Shift` 点选或在泳道空白处拖框，可一起移动或删除字幕、片段、标记；主轨镜头可成组拖动排序，删除时只移除它们关联的视频。
- 打开期间文件被 Agent（`html_spec.py apply`）或其他程序改动时，编辑器自动读入：没有未保存的修改就直接换成新内容，有的话让用户选「载入新版本」或「保留我的修改」（之后保存会覆盖外部修改）。新内容不符合格式时保持原内容并提示，保存仍按冲突拦截。Agent 写入后不必让用户重新打开文件；载入时新建或改动的地方闪一下强调色，删除的镜头留一个警告色残影后淡出。
- 项目规格只有一个文件，始终原地更新，**不另建新的 `.kpldoc`**。已确认/定稿的规格不能在编辑器里改；用户明确要求修改时，用 `html_spec.py apply` 的单条 `state` 操作把它改回草稿（version 自动加一，记录用户决定的来源），再按草稿修改。

## 首次准备与交付

1. 默认使用随技能分发的共享程序 `native-prototype/bin/win-x64/KPL规格编辑器.exe`，不为每份文档复制程序。该目录包含配套 WebView2 SDK 组件和构建清单；运行 `python "<KPL>/scripts/editor_bundle.py"` 检查程序和构建输入是否匹配。清单是变更检查，不是数字签名或安全认证。程序需要 64 位 Windows、已安装的 .NET Framework 4.8 和 WebView2 Runtime；运行时不随包附带，缺失时说明并等待用户决定，不自动下载或安装。完整源码、构建方式和组件许可见 `native-prototype/源码与构建.html`；构建默认使用包内 SDK 组件，也可用 `--csc`、`--core`、`--loader` 指定其他已有组件。输出到新的空目录，不覆盖共享程序。运行时参考 [Microsoft 官方文档](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution)。
2. 在**目标桌面用户账户**下运行只读检查。脚本用系统 API 自行比对运行它的账户与当前会话里登录桌面的用户（中文用户名同样适用），不需要也不要读取 `whoami` 的输出再传入；隔离执行账户的注册表不能代表桌面账户：

   ```powershell
   python "<KPL>/scripts/editor_ready.py" check
   ```

   结果的 `plan` 是不写入的下一步建议，并列出当前目标、新目标和旧程序是否存在。`ready` 表示文件、运行时位置和 Windows 解析的 `.kpldoc` 打开命令检查符合，**不是实测界面或保存通过**。`wrong_user_context` 表示运行脚本的账户不是桌面用户（`checks.account` 与 `checks.desktop_account`），需在桌面用户上下文检查；`target_account_required` 表示当前会话没有桌面用户（如后台服务），可用 `--desktop-account` 指明；`editor_missing`、`runtime_missing`、`association_conflict`、`protected_choice` 和 `inspection_error` 分别说明原因。不能以隔离账户的 `needs_setup` 判定用户桌面未设置。
3. `ready` 就跳过设置。如果是该桌面账户下的 `needs_setup`，先取得此机器首次设置的明确授权，再运行下列操作；关联仅限当前用户 `.kpldoc`，不改 `.html`。`authorization-ref` 只是记录授权来源，文字本身不能证明授权。

   ```powershell
   python "<KPL>/scripts/editor_ready.py" setup --authorization-ref "<本次明确授权的来源>"
   ```

   如果 `plan.next_step` 是 `authorize_owned_rebind`，向用户展示 `current_target` 和 `requested_target`，得到针对这两个路径的明确替换授权后才运行：

   ```powershell
   python "<KPL>/scripts/editor_ready.py" setup --expected-current "<检查结果中的原路径>" --authorization-ref "<用户明确同意替换此关联的来源>"
   ```

   仅完整匹配 KPL 自有记录、无受保护选择、原路径未变化时可重绑定；自有判断依据注册表标记和结构，不是不可伪造的所有权证明。旧文件不存在也可明确授权修复。其他应用的关联、额外记录或 `protected_choice` 不自动覆盖，交由用户在 Windows“默认应用/打开方式”中选择打包编辑器。若 PowerShell 策略、签名或权限拒绝脚本，保留策略和关联，向用户说明并使用系统界面；不得绕过策略。设置后以再次检查的 Windows 实际打开命令为准，只有返回 `ready` 才报告绑定成功；失败、超时或结果不明先核对实际状态，不盲目重试。

   需要撤回自有重绑定时，旧程序仍可用且用户明确同意的情况下，可将上面命令中的 `--exe` 指向旧程序、`--expected-current` 指向当前程序并提供新的授权来源；同样先检查并复核。若只需移除本工具仍完整拥有的关联，得到明确授权后可运行 `native-prototype/file-association.ps1 -Action Uninstall -Executable "<当前关联程序>"`；受保护选择交由用户在系统设置处理。脚本或策略拒绝时不删除、不改安全设置。用户自编译程序也可用 `--exe` 指定，不能自动替换现有关联或将关联指向临时测试副本。
4. 完成准备后交付项目中唯一的 `.kpldoc`，告知用户双击、解锁、编辑、保存。**Agent 不制作 HTML 副本**：需要交给没有编辑器的同事时，由用户在编辑器里点“导出”，选“导出 HTML 交接包…”，自选位置得到一个含只读 HTML 与所需资产的 zip，解压后打开即可看到图片和视频。编辑器不可用时，解释原因；与用户商定后，新项目可选 `init --format html`。浏览器编辑和权限的限制见 [用户可读交付](user-delivery.md)。不要把副本或失败当作已写回项目。

## 用户修改后继续

先读当前指针及实际文件、核对哈希和修订；用户保存会使先前绑定和索引过期。比较稳定 ID、镜头顺序、素材引用、秒数和全局设置，询问含糊的变更；检查受影响镜头、相邻切点及整片结论，保留无关结果。核对后显式重新选择当前文件并更新派生状态绑定，相关验收重新检查，不能自动恢复 PASS。若两个窗口或 Agent 都在写，优先暂停并核对文件；没有真实界面交互或动态播放证据时相应检查仍未验证。
