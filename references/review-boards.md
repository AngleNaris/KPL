# 本地审片板：序列、运动与切点

标准 KPL 项目通过 [项目工具](project-structure.md) 的 `board` 发布中文名页面到用户区、索引到 `.kpl`；下述 `--out` 用于旧项目或 Agent 临时工作区。

多镜导演及资产审查先根据已确认顺序/时长建立并实际打开分段序列总览、索引和关键切点板，再决定哪些疑点需要原图细看；记录回看理由与范围。缩略图无法辨认的脸、手、道具、小字等保持未验证；不是默认逐张查看所有原图。工具或图像查看能力不可用时报告阻塞或降级理由，不静默绕过。也可按需比较单镜动作采样；只读已授权素材，不调用生成模型。依赖当前机器已有的 Python、Pillow、FFmpeg/ffprobe 和中文字体，不自动下载安装。纯图片序列不需要 FFmpeg；无法读取的素材在页面与索引中标为缺失/无效，不冒充完整结果。需要看真实动作、文字或受力时仍要打开原始素材与正常速度的连剪；缩略图、静帧和分数不能证明动态通过。

## 准备唯一有序清单

从现有规格和真实编排提取镜头顺序、实际素材与采用窗，人工核对后创建一份本次清单；不要让工具猜测镜头顺序或把生成提示词当观察。格式见 [示例清单](../assets/review-manifest.example.json)，示例路径只是占位。顶层 `version` 为 1，`shots` 为顺序数组。每项：

- `id`：唯一镜头 ID；`section`：分段名称，变化时另起页；`media`：相对于清单或绝对的实际图片/视频路径。
- `duration`：入片时长（秒）；`timeline_start`：时间线开始秒数，省略则从前镜结束顺推并在索引标记为推导。时间线重叠或变速不在当前支持范围，须先另行核对，工具会拒绝而不是猜测。
- 视频 `in/out`：采用窗，单位为相对该视频**首个解码显示帧**的秒数，出点不包含；省略时默认为 `0/duration`。`out - in` 必须等于 `duration`。图片视为静态，不伪造视频帧。
- `version`：人工提供的版本标记，工具在图上标为“声明版本”；可选 `sha256` 为预期的小写 SHA256，不匹配时显示警告并标记部分结果。未写版本时图上显示实际哈希前缀。`planned_action` 是计划，不是实际观察。
- 可选 `spec` 是实际规格文件路径；它的路径和哈希会进入索引。新文件名、哈希和版本以真实文件为准，未经授权不复制或上传私人素材。

## 三种命令

以下将 `<KPL目录>`、`<清单.json>` 和 `<新输出目录>` 换成实际路径。输出目录的父目录必须存在，输出目录本身必须不存在；工具不会覆盖原素材或已有输出。

```sh
python "<KPL目录>/scripts/review_boards.py" sequence --manifest "<清单.json>" --out "<新输出目录>"
python "<KPL目录>/scripts/review_boards.py" motion --manifest "<清单.json>" --shot S001 --interval 0.5 --out "<新输出目录>"
python "<KPL目录>/scripts/review_boards.py" cut --manifest "<清单.json>" --left S001 --right S002 --samples 3 --interval 0.1 --cut-type "连续动作" --out "<新输出目录>"
python "<KPL目录>/scripts/review_boards.py" verify "<新输出目录>/index.json"
```

- `sequence` 按清单顺序、段落和每页最多 9 镜分页；缩略图不裁切主体。格子是等宽版面，页底时间条依据该页实际时间线位置和时长成比例，空隙不会被当成镜头；跨页不能仅凭条宽直接比较。图中标示 ID、入片时长、时间线位置、声明版本/实际哈希与视频代表帧。`--page-size` 可设 1–9。
- `motion` 保留采用窗首尾帧和固定间隔基准，再按相邻帧的低分辨率灰度平均差补充候选。`--interval` 单位为秒；`--candidates` 为 0–6；`--threshold` 为 0–1，`--gap` 为候选之间的最小秒数。候选只提示画面变化，镜头移动、闪光、剪切、噪声都可能产生高分，不是语义动作识别。图上的时间尺按窗内实际可见时间排列样本，不把不等间隔画成等时。
- `cut` 比较清单中时间线相接的相邻镜头；页面以秒显示源时间、切点、采用窗和实际采样间隔。`--samples` 为每侧 1–3 张画面，`--interval` 是期望的秒数，依据实际解码时间戳向两侧选取，实际间隔可不同；技术索引保留帧号。短镜只显示实际可用画面。旧参数 `--frames/--stride` 仍可读取为采样张数/解码步长，新审查优先用秒。`--cut-type` 是人工提供的待核查意图，不是自动通过判定。

## 时间戳、索引与失效

视频帧使用 ffprobe 解码显示顺序的 `best_effort_timestamp` 与流 `time_base`，不是平均帧率乘法。每帧在索引同时记录原始 PTS、时间基、从首个显示帧起算的源时间、帧号、显示区间和采用窗内可见区间。非整帧入/出点使用 `[PTS, 下一帧PTS)` 的显示保持模型，选择与采用窗有交集的帧；若实际剪辑软件使用不同的边界取帧策略，须对照该软件的真实输出。缺失、重复或非递增时间戳、无法确定末帧覆盖范围的素材标为无效，不猜测帧率补齐。

运动板的固定请求点可能落在同一帧显示区间；索引的 `requested_times` 保存所有请求，`actual_seconds` 和 `visible_interval` 保存实际取到的帧和可见时段。时间尺使用可见区间的起点；图上 `源相对` 以秒表示相对第一个解码显示帧的时间，显示数字四舍五入到毫秒，不修改计划；原始 PTS、时间基及帧号留在技术索引。切点板也包含每侧实际采样间隔，不把普通静态图片标为视频帧。

每次输出包含 PNG 页面和 `index.json`：源路径与 SHA256、原始清单/规格哈希、采用窗、时间戳、采样角色、输出页/格位、可见标签、工具版本/参数、字体和依赖版本。`review_status` 始终为 `unverified`。在同一 KPL 规格中登记页面和索引的实际路径/哈希，并在审查记录关联对应素材版本、镜头、查看工具和具体发现；先真正打开审片板，再根据需要回到原始图片或视频。输出没有更新创作规格，也不授权生成或发布。

使用 `verify` 检查清单、规格、源素材、输出页、工具代码和字体是否变化；有变更/缺失返回 `stale:true` 与退出码 1，须重新建立相应板并复核。完整运行但有缺失或版本不符时，生成命令返回 `status:partial`，仍不是验收通过。命令错误退出码为 2。索引本身可被编辑，需将 `index.json` 的哈希另记在规格里；哈希一致也不证明实际观看或内容正确。
