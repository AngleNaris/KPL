KPL 编辑器：源码与构建

技能中同时提供 Windows x64 共享编辑器和完整可修改源码。一份程序服务多份 .kpldoc，不需要复制进每个项目。

源码在哪里

  • src/Host.cs：窗口、WebView2、原生接口和资源访问。
  • src/DocumentSession.cs：文档读取、保存与冲突检查。
  • ui/index.html、ui/tokens.css、ui/app.css、ui/app.js：界面源码；ui/ 还包含辅助说明及素材脚本。
  • assets/：图标与应用内标识。make_icon.py 由设计原图生成 kpl.ico，需已有的 Pillow；trace_logo.py 把横版原图描摹成矢量 logo-wide.svg，需 numpy 和 Pillow，并会直接改写 ui/index.html 中 KPL_LOGO_START/END 之间的标识精灵，不要手改那一段。两者都不参与程序构建，但 kpl.ico 是构建输入，改后需重新构建并更新清单。
  • build.py、native_doc.py、file-association.ps1、tests/ 和 examples/：构建、格式转换、打开方式、测试及合成示例。../scripts/html_spec.py 和 ../scripts/editor_bundle.py 也是构建输入。

直接使用与依赖

预编译文件在 bin/win-x64/，包含编辑器和两个 Microsoft WebView2 SDK 1.0.3179.45 组件。运行需要 Windows x64、.NET Framework 4.8 和 WebView2 Runtime；后两者由系统提供，不包含在技能中。不会自动下载或安装。程序尚未作为正式签名发行版验证；系统安全提示需由用户判断。

修改并构建

在技能目录打开终端，使用已有 Python 3.10 或更新版本及 Windows .NET Framework C# 编译器。本次重建使用 Python 3.14.0 和 C# 编译器 4.8.4084.0；其他版本需要自行验证。默认从当前技能包使用 WebView2 组件，默认编译器取当前 Windows 目录下的 Microsoft.NET/Framework64/v4.0.30319/csc.exe；可用 --csc 指定其他已有编译器。如果组件需要替换，使用 --core 和 --loader 指向匹配的现有 SDK 文件。

python native-prototype/build.py --out-dir "<用户可写的新空目录>"

构建拒绝覆盖非空目录，不下载依赖。新目录会包含程序、两个组件及 manifest.json。重新构建前请保留原始程序与文档；若需让 Windows 用新程序打开文件，先检查已有打开方式并由用户决定，不自动替换关联。

ui/make_preview_assets.py 仅用于生成可选的合成预览图片，不参与程序构建。它另需已有的 Pillow（本次测试环境为 12.1.1）及脚本指定的中文字体；字体路径不适用时可先在脚本中改为本机已有字体。技能包不附带 Pillow 或字体，也不会自动安装。

核对源码与程序

python scripts/editor_bundle.py
python scripts/editor_bundle.py --bundle "<新构建目录>"

matching 表示当前构建输入和程序与该清单记录一致；清单由构建脚本记录输入和输出的 SHA-256，不是签名或第三方认证。修改源码后旧清单会显示变化；重新构建会产生新的清单。编译结果可能因编译器版本等因素不同，不保证逐字节重现。
